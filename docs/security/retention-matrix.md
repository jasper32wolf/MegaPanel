# Хранение данных: проверенный контур аналитики

Отчёт оператора охватывает календарные сутки UTC, текущие сутки берёт из сырых событий, а завершённые — из суточных итогов. Сессии суммируются **по дням**, это не число уникальных посетителей за период. При менее чем пяти сессиях по странице за выбранный период точные числа в API и интерфейсе скрываются. Отзыв выполняется только для известного браузеру идентификатора текущей сессии: он не удаляет историю других устройств и уже необратимо агрегированные показатели. Запрос на удаление повторяется в той же вкладке после восстановления связи; закрытие вкладки до успешного ответа может помешать удалению — оставшиеся события всё равно подпадают под общий срок хранения.

Публичные шаблоны политики требуют юридической проверки **до публикации**. Сроки фиксируются во входном snapshot candidate; смена настроек после сборки блокирует публикацию/rollback нового candidate с зафиксированной политикой до новой сборки и юридического review. Старые releases и старые Caddy vhosts не обновляются автоматически: для работающего у посетителя отзыва нужны новый candidate, подтверждённая публикация и обновлённый vhost с точными POST-маршрутами `/api/v1/telemetry/collect` и `/api/v1/telemetry/revoke`. До этого удаление по обращению и плановая очистка raw остаются средствами защиты. Регулярная задача очистки работает только пока включён worker: при остановке сервиса требуется эксплуатационный контроль просроченных записей.
